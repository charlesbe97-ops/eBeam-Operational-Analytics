# Power BI Data Model

## Overview

The Power BI model organizes the prepared analytical datasets into a structured model designed for monthly and daily operational analysis.

The model separates calendar information, operational process data, downtime records, daily summaries, monthly KPI results, service-level analysis, and production information.

## Model Structure

```text
                         ┌───────────────┐
                         │   Calendario  │
                         └───────┬───────┘
                                 │
                  ┌──────────────┼──────────────┐
                  │              │              │
                  ▼              ▼              ▼
        ┌────────────────┐ ┌──────────────┐ ┌────────────────┐
        │Historico_      │ │Historico_    │ │Resumen_Diario  │
        │Proceso         │ │Paros         │ │                │
        └────────────────┘ └──────────────┘ └────────────────┘


                         ┌───────────────┐
                         │  KPI_Mensual  │
                         └───────┬───────┘
                                 │
                    ┌────────────┴────────────┐
                    │                         │
                    ▼                         ▼
          ┌──────────────────┐      ┌──────────────────┐
          │Tiempos_por_      │      │Tarimas_por_      │
          │Servicio          │      │Servicio          │
          └──────────────────┘      └──────────────────┘
```

## Main Tables

### Calendario

The calendar table provides the date dimension used to analyze operational information over time.

It supports daily filtering and time-based analysis across the operational datasets.

### Historico_Proceso

Contains historical process-level operational information prepared by the Python pipeline.

It supports analysis of process execution and operational performance.

### Historico_Paros

Contains historical downtime records.

It supports analysis of:

- Downtime duration.
- Number of downtime events.
- Interlock events.
- Daily downtime behavior.
- Pareto analysis.

### Resumen_Diario

Provides daily summarized operational information used by the dashboard for daily performance visualization.

### KPI_Mensual

Contains the monthly operational KPI results generated by the Python analytical pipeline.

It provides the monthly context for the main operational indicators displayed in the dashboard.

### Tiempos_por_Servicio

Contains service-level processing time information.

It supports analysis of operational time by service and product/service category.

### Tarimas_por_Servicio

Contains production information at the service level, including treated pallet quantities.

It supports production analysis and monthly operational activity monitoring.

### Historico_Master

Contains historical master-log information prepared from the operational records.

It supports the integration and classification of service-level operational information.

### Historico_BeamON

Contains historical Beam ON information used to support utilization and operational activity analysis.

### Historico_Auditoria

Contains data-quality audit results generated during the Python processing stage.

It supports the identification and monitoring of incomplete operational records.

## Relationship Design

The model uses the `Calendario` table as a shared date dimension for the daily operational datasets.

`KPI_Mensual` provides the monthly context for the service-level analytical tables:

```text
KPI_Mensual
    │
    ├── Tiempos_por_Servicio
    │
    └── Tarimas_por_Servicio
```

The service-level tables remain separate rather than being directly related to each other.

This avoids creating a direct fact-to-fact relationship between service-time and production tables and allows each analytical dataset to remain focused on its own business process.

## Modeling Approach

The model follows a separation between:

- **Date dimension** — Calendar and time filtering.
- **Operational fact tables** — Process, downtime, Beam ON, and daily operational data.
- **Monthly analytical results** — Monthly KPI values.
- **Service-level analytical tables** — Processing times and treated pallets.
- **Audit data** — Data-quality information generated by the Python pipeline.

This structure supports interactive filtering while keeping different analytical domains separated.

## Data Flow

The overall analytical architecture is:

```text
Raw Operational Records
          │
          ▼
       Python
          │
          ├── Cleaning
          ├── Transformation
          ├── KPI calculations
          ├── Data-quality audits
          └── Historical preparation
          │
          ▼
   Prepared CSV datasets
          │
          ▼
       Power BI
          │
          ├── Data model
          ├── DAX measures
          ├── Interactive filters
          └── Visualizations
          │
          ▼
   Operational Analysis
```
